# PanelPro

> 基于 STM32F407VET6 的智能中控设备固件 —— FreeRTOS + LVGL 界面，支持通过 HC-08 蓝牙的固件空中升级（OTA）。

## 概览

一句话：**双工程固件 —— 独立 Bootloader + 带 LVGL 界面的 App（Arc 控件控制电机转速、色环切换 RGB 灯光）；升级时经蓝牙把新固件写入 STM32 内部 Flash，校验通过后自动跳转运行。**

最近一次完整升级（蓝牙链路）的关键数字：

| 项 | 值 |
|---|---|
| 固件大小 | 451,648 字节（≈ 441 KB） |
| 传输帧数 | 1882 帧 |
| 重传次数 | 0 |
| 全程耗时 | 1573 秒（约 26 分钟；瓶颈是 9600 bps 的串口带宽） |
| 目标区容量 | App 区 464 KB（475,136 字节），已用约 95% |

## 仓库结构

| 目录 | 是什么 | 说明 |
|---|---|---|
| `PanelPro/` | **App 工程**（FreeRTOS + LVGL） | 链接于 `0x0800C000`，日常运行的固件 |
| `F407_IAR/` | **Bootloader 工程** | 链接于 `0x08000000`（32 KB）。上电先跑它：校验通过 → 跳转 App；否则停在 OTA 等待循环 |
| `py/` | **上位机 OTA 工具**（Python + bleak） | 组帧、发送、超时重传、断点续传；经电脑蓝牙 → HC-08 |

## 升级链路

```
PC (Python) ──BLE──▶ HC-08 ──UART 9600──▶ STM32F407
```

- 蓝牙协议栈在两端的设备里：电脑侧（系统蓝牙栈 + `bleak`）和 HC-08（模块自带固件）——**STM32 侧只见 UART 字节流**。
- 升级使用自定义帧协议：`AA | CMD | LEN | DATA | XOR8 | 55`；PC 与 MCU 是链路上唯二"懂协议"的两个端点。

## 关键技术点

**1. 双工程架构 + 唯一跳转凭证**
Bootloader 只凭 App 区元数据中的 `magic`（`0xA5A5A5A5`）决定是否跳转；magic 只在一次升级**完整成功**的最后一步写入。

**2. Fail-safe：任何中断都不会变砖**
升级一开始先**擦除 magic** ⇒ 此后无论断线、断电、PC 崩溃还是校验失败，重启后 Bootloader 都会停在 OTA 循环等待重试 —— **永远不会跳进半截 App**。擦除只发生在 `CMD_START` 一次，范围仅限元数据区与 App 区，Bootloader 区全程静默。

**3. 传输可靠性三件套**
- **XOR8**（单帧级）：保证字节未损坏，坏帧丢弃、重新对齐；
- **CRC32**（整包级）：收尾总校验，兜住"每帧都对但顺序 / 数量错"的语义错误；
- **超时重传 + 幂等**：丢包即重发；重复帧不重复写入、回 ACK（不回 NACK —— 避免"重发-拒绝"死循环）。

**4. 索引制寻址 ⇒ 断点续传**
写入地址由块号算出（`地址 = APP_BASE + (块号−1) × 240`），不依赖板子记录进度 —— 传输中断后可从断点续传（`--resume N`）。

## 构建与升级

**构建**（Keil MDK）：
- App：`PanelPro/MDK-ARM/pro.uvprojx` 编译；After Build 已配置 `fromelf --bin`，自动生成 `py/pro.bin`
- Bootloader：`F407_IAR/MDK-ARM/F407_IAR.uvprojx` 编译

**升级**：
1. 板子进入 OTA 模式：屏幕 → 关于页 → "系统升级" → 二次确认（擦除 magic 并复位，停在 OTA 循环）
2. 电脑执行（Python + `bleak`）：`py ota_tool_ble.py --gap 3`（`--scan` 扫设备 / `--probe` 探活 / `--resume N` 断点续传）
3. 完成后板子自动复位，跳转运行新固件
